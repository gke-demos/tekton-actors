# Fork `tektoncd/pipeline` with Native `actor` WorkspaceBinding and Step Supervisor

We fork `tektoncd/pipeline` (`gke-demos/tekton-pipeline`) to add an `actor` source on `WorkspaceBinding` and an Actor-backed `TaskRun`/`PipelineRun` execution path rather than wrapping tasks in `CustomRun` CRDs. This lets byte-for-byte identical `tekton.dev/v1` `Pipeline` and `Task` manifests run on both Substrate `Actor`s and stock Kubernetes `Pod`+`PVC`s for a true head-to-head comparison. Because Substrate `v1.0.0` treats any PID 1 exit inside a sandbox as `ACTOR_STATE_CRASHED` and offers no `Control.Exec` RPC, each `ActorTemplate` step container mounts our static `Step Supervisor` binary via read-only `ImageVolumeSource` as PID 1 to run steps over `atenet-router`, stream logs, and capture `/tekton/results/*` while keeping the sandbox suspendable.
